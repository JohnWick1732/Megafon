# Источники и журнал утверждений

Открытый HTTPS-адрес можно загрузить через `source-add` с разрешённым доменом. Если среда не может скачать страницу или она требует JavaScript, подготовь короткую точно скопированную выдержку в TXT и передай через `--file … --trust public --origin <URL>`. Укажи конкретный раздел в тексте выдержки. У файла без ссылки происхождение укажи в `--title`. Исходный файл остаётся в `inputs/` или в своём исходном расположении.

Используй `source-show`, чтобы увидеть номера строк снимка. Для исходного CSV или XLSX уточняй номер исходной строки и лист в выжимке. Для PDF сверяй извлечённый текст с номером страницы. Ссылайся в Markdown на паспорт источника и исходный URL. Номер строки снимка относится к локальному слепку. Извлечение страницы не запускает код сайта и может пропустить динамическое содержимое.

`claims-add` принимает JSON-массив. Допустимые виды: `fact`, `hypothesis`, `forecast`, `inference`, `decision`, `synthetic`. ID уникальны внутри кейса. Для вывода укажи уже записанные основания. Для факта нужна хотя бы одна точная цитата из несинтетического источника. Скрипт проверяет совпадение текста, модель отдельно проверяет, действительно ли из него следует утверждение.

```json
[
  {
    "id": "F01",
    "kind": "fact",
    "text": "Утверждение, подтверждённое указанной строкой.",
    "evidence": [
      {"source": "S-…", "line_start": 2, "line_end": 2, "quote": "Точная цитата"}
    ]
  },
  {
    "id": "I01",
    "kind": "inference",
    "text": "Вывод для решения.",
    "depends_on": ["F01"]
  }
]
```

Если нашлась поправка, добавь новое утверждение со ссылкой на исходное и отметь ошибку в текущем артефакте до подтверждения. Не перезаписывай старый ID. Для замеров укажи ID события, этап, пояснение и известные значения. Если одна запись описывает весь прогон, её значения не складывай повторно с детализацией тех же действий.
